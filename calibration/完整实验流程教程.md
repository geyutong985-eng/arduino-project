# 完整实验流程教程

本文说明从预实验采集、运行计算脚本，到上传正式实验程序的完整操作流程。适用于 Windows 电脑；文末也写了换到 Mac 时的对应命令。

## 1. 文件关系

本项目里有两个 Arduino 程序：

```text
pretest_calibration/pretest_calibration.ino
main/main.ino
```

它们的分工是：

| 文件 | 用途 |
|---|---|
| `pretest_calibration/pretest_calibration.ino` | 预实验采集程序，用来采集每位参与者的动作数据 |
| `tools/compute_dtw_thresholds.ps1` | 计算脚本，把预实验数据转换成正式实验可用的模板 |
| `main/DTWCalibrationData.h` | 自动生成的个人模板头文件，不需要手动改 |
| `main/main.ino` | 正式实验程序，上传到 ESP32 后会读取 `DTWCalibrationData.h` |

最终流程是：

```text
上传预实验程序
-> 串口采集 participant 的 session.txt
-> 运行 compute_dtw_thresholds.ps1
-> 自动生成 main/DTWCalibrationData.h
-> 上传正式实验程序 main/main.ino
-> 正式实验
```

## 2. 预实验采集

先上传：

```text
pretest_calibration/pretest_calibration.ino
```

打开 Arduino IDE 串口监视器：

```text
波特率：115200
```

预实验串口命令：

| 命令 | 功能 |
|---|---|
| `n` | 记录 neutral pose |
| `f` | 记录 Flex 伸直基线 |
| `b` | 记录 Flex 弯曲基线 |
| `1` | 选择 `HALF_RAISED` 动作 |
| `2` | 选择 `PICKING` 动作 |
| `s` | 开始当前 trial |
| `e` | 结束当前 trial |
| `a` | 标记刚结束的 trial 合格 |
| `r` | 标记刚结束的 trial 不合格 |
| `h` | 打印帮助 |

推荐顺序：

1. 参与者保持自然放松姿态，输入 `n`。
2. 参与者保持伸直姿态，输入 `f`。
3. 参与者保持目标弯曲姿态，输入 `b`。
4. 输入 `1`，选择 `HALF_RAISED`。
5. 每次 trial：输入 `s`，让参与者从起始位置做到 Half-raised，完成后输入 `e`，合格输入 `a`，不合格输入 `r`。
6. `HALF_RAISED` 至少保留 3 次 accepted trial。
7. 输入 `2`，选择 `PICKING`。
8. 每次 trial：输入 `s`，让参与者从 Half-raised 做到 Picking，完成后输入 `e`，合格输入 `a`，不合格输入 `r`。
9. `PICKING` 至少保留 3 次 accepted trial。

预实验结束后，把串口监视器里的完整输出复制保存为一个 `.txt` 文件。

推荐保存位置：

```text
calibration/raw/participant_001/session.txt
```

第二位参与者可以保存为：

```text
calibration/raw/participant_002/session.txt
```

文件名可以换，但推荐每位参与者一个文件夹，后面运行命令不容易混。

## 3. Windows PowerShell 运行脚本

打开 Windows PowerShell。

先进入项目根目录。复制下面这一整行，粘贴到 PowerShell，按 Enter：

```powershell
cd "C:\Users\m1895\Desktop\obsidian_cc_test\01_学校课程\智能硬件基础\arduino-project"
```

确认当前路径已经变成：

```text
PS C:\Users\m1895\Desktop\obsidian_cc_test\01_学校课程\智能硬件基础\arduino-project>
```

然后运行计算脚本。

如果你要计算 `participant_001/session.txt`，复制这一行：

```powershell
.\tools\compute_dtw_thresholds.ps1 -SessionFile .\calibration\raw\participant_001\session.txt
```

如果你要计算第二位参与者，例如 `participant_002/session.txt`，复制这一行：

```powershell
.\tools\compute_dtw_thresholds.ps1 -SessionFile .\calibration\raw\participant_002\session.txt
```

如果你的文件名是 `participant002_session.txt`，例如放在：

```text
calibration/raw/participant_002/participant002_session.txt
```

那命令就写成：

```powershell
.\tools\compute_dtw_thresholds.ps1 -SessionFile .\calibration\raw\participant_002\participant002_session.txt
```

规则就是：

```powershell
.\tools\compute_dtw_thresholds.ps1 -SessionFile 你的txt文件路径
```

## 4. PowerShell 拦截脚本怎么办

如果 PowerShell 不让运行 `.ps1` 文件，使用下面这种写法：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\compute_dtw_thresholds.ps1 -SessionFile .\calibration\raw\participant_001\session.txt
```

第二位参与者则改成：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\compute_dtw_thresholds.ps1 -SessionFile .\calibration\raw\participant_002\session.txt
```

这里需要改的只有最后的 `-SessionFile` 后面的路径。

## 5. 运行成功后会看到什么

成功时 PowerShell 会输出类似：

```text
Generated .\calibration\dtw_threshold_report.csv
Generated .\calibration\dtw_templates.json
Generated .\main\DTWCalibrationData.h
Accepted trials: HALF_RAISED#1, HALF_RAISED#2, HALF_RAISED#3, PICKING#4, PICKING#5, PICKING#6
Flex calibration: straight=1268, bent=1737
```

这表示脚本已经跑完。

它会生成或更新 3 个文件：

```text
calibration/dtw_threshold_report.csv
calibration/dtw_templates.json
main/DTWCalibrationData.h
```

其中最重要的是：

```text
main/DTWCalibrationData.h
```

正式实验程序会直接读取这个文件。

注意：每次运行脚本，这 3 个文件都会被覆盖更新。它们永远代表“最近一次运行脚本的参与者”。

## 6. 跑完脚本后做什么

运行脚本成功后，上传正式实验程序：

```text
main/main.ino
```

上传到 ESP32 后，正式实验程序会使用刚刚生成的：

```text
main/DTWCalibrationData.h
```

不需要手动改 `DTWCalibrationData.h`。

如果换了参与者，需要重新做：

```text
保存该参与者 session.txt
-> 跑 compute_dtw_thresholds.ps1
-> 重新上传 main/main.ino
```

原因是 `DTWCalibrationData.h` 会被编译进 ESP32 程序里。ESP32 不是运行时从电脑读取这个 `.h` 文件，所以每换参与者都要重新上传正式程序。

## 7. 正式实验串口命令

正式实验程序：

```text
main/main.ino
```

常用命令：

| 命令 | 功能 |
|---|---|
| `m` | 重新记录正式实验当前 neutral pose |
| `q` | 开关 DTW 匹配结果串口输出 |
| `s` | 查看 Flex 状态 |
| `f` | 手动重新校准 Flex 伸直 |
| `b` | 手动重新校准 Flex 弯曲 |
| `h` | 打印帮助 |

正常情况下，Flex 伸直/弯曲基线已经从预实验数据写入 `DTWCalibrationData.h`，正式实验不需要再输入 `f` 和 `b`。

只有在传感器位置变了、贴歪了、重新绑了，才需要现场输入 `f` 和 `b` 临时覆盖。

正式实验开始前建议：

1. 让参与者回到和预实验一致的 neutral pose。
2. 输入 `m`。
3. 开始正式实验动作。

## 8. 串口输出怎么看

正式实验里可能会看到：

```text
[COMBINED] Posture: UNKNOWN | Score: 999.0000 | DTW: UNKNOWN
```

这里的 `COMBINED Posture` 是旧的静态 IMU 分类器，不是当前 DTW 主判断。它显示 `UNKNOWN` 不一定代表 DTW 失败。

重点看：

```text
[DTW] frames=60 half=.../... picking=.../... best=...
```

例如：

```text
[DTW] frames=60 half=0.2100/0.3355 picking=1.2000/0.1383 best=HALF_RAISED
```

含义是：

```text
half = 当前动作和 HALF_RAISED 模板的距离 / HALF_RAISED 阈值
picking = 当前动作和 PICKING 模板的距离 / PICKING 阈值
best = 当前最像哪个动作
```

只有左边的距离小于右边的阈值，才会认为匹配成功。

如果一直是：

```text
best=UNKNOWN
```

通常有几种原因：

- 做的动作不是完整动作，只是在保持某个姿势。
- 正式实验动作速度和预实验差太多。
- 传感器佩戴位置和预实验不一致。
- 参与者不是刚才生成 `DTWCalibrationData.h` 的那个人。
- 忘记重新上传 `main/main.ino`。

## 9. Mac 上怎么跑

如果换到 Mac，路径写法会变成 `/`，不是 Windows 的 `\`。

打开 Terminal，进入项目根目录。例如项目放在桌面：

```bash
cd ~/Desktop/obsidian_cc_test/01_学校课程/智能硬件基础/arduino-project
```

这个脚本是 PowerShell 脚本，所以 Mac 上需要安装 PowerShell。安装后命令通常是 `pwsh`。

运行 participant_001：

```bash
pwsh -ExecutionPolicy Bypass -File ./tools/compute_dtw_thresholds.ps1 -SessionFile ./calibration/raw/participant_001/session.txt
```

运行 participant_002：

```bash
pwsh -ExecutionPolicy Bypass -File ./tools/compute_dtw_thresholds.ps1 -SessionFile ./calibration/raw/participant_002/session.txt
```

Mac 上运行成功后，也会生成同样 3 个文件：

```text
calibration/dtw_threshold_report.csv
calibration/dtw_templates.json
main/DTWCalibrationData.h
```

然后同样上传：

```text
main/main.ino
```

## 10. 最容易弄错的地方

不要用这些旧文件跑 DTW 主流程：

```text
calibration/raw/natural_down.txt
calibration/raw/half_raised.txt
calibration/raw/picking.txt
```

这些是旧的静态姿态阈值流程文件。

现在 DTW 主流程应该用每位参与者自己的完整 session 文件：

```text
calibration/raw/participant_001/session.txt
calibration/raw/participant_002/session.txt
```

不要手动修改：

```text
main/DTWCalibrationData.h
```

它是脚本自动生成的。手动改了，下次运行脚本也会被覆盖。

每换一位参与者，都要：

```text
跑脚本
重新上传 main/main.ino
```
